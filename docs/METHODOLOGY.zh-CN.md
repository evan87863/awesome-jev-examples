# 收录与核验方法

[返回首页](../README.zh-CN.md)

## 范围

主要收录实际使用 TypeSafe Jev 的公开项目、官方带实现思路的教程，以及开发者对自己集成工作的报告。教程、SDK、应用、评测分别标明类型，不把它们全部称为已落地案例。Jev 风格的开源模型替代品暂不收录，避免混淆“使用 Jev”和“受 Jev 启发”。

## 证据等级

| 数据值 | 含义 | 不意味着 |
| --- | --- | --- |
| `readme-reviewed` | 已读原作者仓库 README，确认描述与 Jev 有明确关系 | 已审计实现、运行或确认效果 |
| `doc-reviewed` | 已读官方教程正文与示例说明 | 已复现官方结果 |
| `doc-excerpt-reviewed` | 已核对官方导语和目录；正文传输不完整 | 已完整审阅教程 |
| `article-reviewed` | 已读作者/开发团队的一手报告 | 已独立复测 |
| `discovery-only` | 从目录或搜索发现具体原始链接 | 已确认原文或视频内容 |

所有当前正式条目的 `reproduction` 为 `not-run`。后续若升级为已复现，必须补充版本或 commit、环境、运行方法、输入、实际输出及失败情况，并调整检查脚本。没有这些证据，不使用“已验证可用”。

`checked_at` 是本仓库核对日期，不是源项目发布日期。`evidence_sha256` 记录本次获取正文的散列，帮助识别后续变化；它不是代码 commit，也不能替代复现证据。传输不完整的文档散列仅对应收到的部分正文。

## 编写规则

1. 保留原作者和原始链接，以自己的话概括用途与学习点。
2. 一个项目一条记录。推文、视频、在线演示放入 `related`，避免多平台重复统计。
3. 不根据名称或聚合目录简介推断已经调用 Jev。
4. 不把高置信度解释为正确性保证；不把类型受限解释为没有判断错误。
5. 不把作者公布的时延、费用、胜率或准确率作为独立测量。
6. 保留有信息价值的失败、混合模型、模拟器和启发式兜底说明。
7. 无法访问的社交原文留在候选区，不从二手标题扩写技术细节。
8. 失效链接先复查：访问超时、反爬、需登录和资源删除不是一回事。

## 数据维护

`data/resources.json` 是正式索引；`data/candidates.json` 是待核验列表。README 与 catalog 文件由脚本生成，避免手工维护多个副本。GitHub Actions 仅执行离线一致性检查，没有创建周期性抓取、API 调用或自动发帖任务。

默认不复制全文、视频、截图或外部代码。原创摘要及维护脚本使用本仓库许可证，外部资源保持原许可证。
